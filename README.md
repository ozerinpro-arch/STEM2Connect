# ResearchLens · STEM2Connect

Веб-лаборатория проверки исследовательских выводов. Загрузить CSV, подтвердить план анализа, увидеть влияние группировки и допущений, открыть расчёт и выгрузить воспроизводимый эксперимент.

## Запустить платформу

Требуется Python 3.11+ и Node.js 20.19+ или 22.12+. Из корня репозитория выполните:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements.txt
npm --prefix frontend ci
npm --prefix frontend run build
.venv/bin/python -m uvicorn backend.main:api --host 127.0.0.1 --port 8000 --workers 1 --no-access-log
```

Откройте http://127.0.0.1:8000 и выберите **Search benchmark**. В синтетическом наборе общие доли A 27% и B 73% меняются на A 55% и B 45% после стандартизации с весами 50/50. Нажмите на полосу графика, чтобы открыть формулу и размеры групп. Для проверки импорта используйте `contracts/fixtures/stable-search.csv`.

Для разработки frontend отдельно запустите `npm --prefix frontend run dev` при работающем backend. Vite проксирует API на порт 8000. В production-сборке FastAPI раздаёт веб-интерфейс и API на одном origin.

## Запуск backend

Из корня репозитория, Python 3.11+.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements.txt
.venv/bin/python -m uvicorn backend.main:api --host 127.0.0.1 --port 8000 --workers 1 --no-access-log
```

- Base URL — `http://127.0.0.1:8000/api/v1`.
- Проверка — `curl -fsS http://127.0.0.1:8000/api/v1/health`.
- Спецификация запущенного API — `http://127.0.0.1:8000/docs`.
- Для frontend используйте proxy на этот адрес и `fetch(..., { credentials: "include" })`. Для прямого доступа с другого origin в пределах одного сайта задайте точный origin через `RESEARCHLENS_FRONTEND_ORIGIN`, например `http://127.0.0.1:5173`. Для HTTPS включите `RESEARCHLENS_SECURE_COOKIE=1`.
- Сервер хранит наборы, планы и запуски в памяти одного процесса. Сессия истекает через час без обращений к её данным. После перезапуска сервера понадобится новый импорт. Идентификаторы ресурсов создаёт API. Идентификаторы из fixtures предназначены для демонстрации контракта.
- CSV поддерживает UTF-8, запятую и первую строку с уникальными именами столбцов. Лимиты — 10 МБ, 50 000 строк, 200 столбцов и 1 000 000 ячеек. Пустые значения видны в схеме и блокируют подтверждение плана при выборе такого столбца. Имена выбранных столбцов и категорий в плане ограничены 4096 символами. Столбцы с целыми числами в безопасном диапазоне JSON определяются как `integer`, остальные как `string`.
- Расчёт поддерживает две выбранные группы, бинарный исход и до 100 страт. Укажите вес каждой наблюдаемой страты. Если для одной из групп в заданной страте нет наблюдений, запуск возвращает `failed` с указанием группы и страты. Повтор с тем же `Idempotency-Key` и планом возвращает существующий запуск.

### Объяснение ИИ

На сервере задайте `RESEARCHLENS_MODEL_URL` (полный HTTPS-адрес совместимого endpoint Chat Completions), `RESEARCHLENS_MODEL` и `RESEARCHLENS_MODEL_KEY`. Endpoint должен поддерживать ответ в формате JSON. Вызов `POST /api/v1/runs/{id}/explanation` следует выполнять после явного выбора пользователя. Адаптер передаёт числовые оценки и условные обозначения групп и страт. При отсутствии конфигурации, сетевой ошибке, тайм-ауте в 12 секунд или недействительных ссылках на оценки API возвращает `503 MODEL_UNAVAILABLE`. Успех проверен на локальном тестовом ответе. Для проверки реального провайдера нужна его конфигурация.

### Экспорт и тесты

`GET /api/v1/runs/{id}/export` скачивает ZIP. Добавьте `?include_data=true` по выбору пользователя, чтобы включить CSV с защитой от интерпретации ячеек как формул. В распакованном архиве выполните `python3 reproduce.py`. Для архива без CSV передайте путь к исходному файлу через `python3 reproduce.py /path/to/original.csv`. Скрипт проверяет контрольные суммы и повторяет расчёт средствами стандартной библиотеки Python.

```sh
.venv/bin/python -m pip check
.venv/bin/python -m unittest backend.test_api -v
npm --prefix frontend run test:e2e
```

Для браузерного теста нужен Chrome. Тесты запускают локальный HTTP-сервер на свободном порту. Они сверяют оба эталона, загружают пользовательский CSV, проверяют лимиты и ошибки, повтор запроса, изоляцию сессий, выгрузку и повторный расчёт в чистом каталоге.
